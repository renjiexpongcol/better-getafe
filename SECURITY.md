# Security Policy

## Reporting a Security Vulnerability

The Better Getafe project takes the security of this application seriously.

If you discover a security vulnerability, please **do not report it through a public GitHub issue, discussion, or pull request**. Public disclosure may expose users or the system to unnecessary risk.

Instead, please report the vulnerability privately to the project maintainers.

### What to Include

Please provide as much of the following information as possible:

* A clear description of the vulnerability
* The affected page, feature, endpoint, or component
* Steps to reproduce the issue
* The potential security impact
* Screenshots, logs, or proof-of-concept details when appropriate
* Any suggested remediation, if available

Please do not include passwords, authentication tokens, personal information, or other sensitive data in your report.

## Response Process

After receiving a vulnerability report, the maintainers will:

1. Review and validate the report.
2. Assess the severity and potential impact.
3. Work on a fix or mitigation.
4. Deploy the necessary security updates.
5. Coordinate responsible disclosure when appropriate.

We ask security researchers to allow reasonable time for a vulnerability to be investigated and addressed before publicly disclosing it.

## Scope

Security reports may include issues involving:

* Authentication and authorization
* Unauthorized access to protected information
* Data exposure
* Injection vulnerabilities
* Cross-site scripting (XSS)
* Cross-site request forgery (CSRF)
* Server-side vulnerabilities
* API security
* Cloud infrastructure configuration
* Secrets or credential exposure
* Dependency vulnerabilities with meaningful security impact

## Out of Scope

The following generally do not qualify as security vulnerabilities unless they demonstrate a meaningful security impact:

* General feature requests
* UI or design issues
* Typographical errors
* Non-security bugs
* Automated scanner reports without demonstrated impact
* Denial-of-service testing against production systems
* Social engineering or phishing attempts against project personnel

## Responsible Disclosure

Please make a reasonable effort to avoid accessing, modifying, deleting, or exposing data that does not belong to you.

Do not perform destructive testing or intentionally disrupt production services.

We appreciate responsible security research and will make a reasonable effort to work with researchers to understand and resolve legitimate security issues.

## Security Updates

Security fixes may be released through normal project updates. Users are encouraged to keep deployments and dependencies up to date.

---

Thank you for helping keep Better Getafe and its users secure.
